# AFIP/ARCA WSLPG Technical Documentation for Python/Django ERP Integration

## Executive Summary

The WSLPG (Web Service de Liquidación Primaria de Granos) is AFIP's SOAP-based web service for the electronic authorization of grain purchase/sale settlements (Liquidación Primaria de Granos), governed by Resolución General 3419/2012 and complementary regulations (RG 3690/2014, RG 3691/2014). The latest version is **v1.24**, published on January 30, 2026. This report covers endpoints, all available SOAP methods, data structures, error handling, open-source implementations, and testing environment details for a Python/Django integration.[^1][^2][^3]

***

## 1. Service Endpoints and Authentication

### WSDL URLs

| Environment | URL |
|---|---|
| **Homologation (testing)** | `https://fwshomo.afip.gov.ar/wslpg/LpgService?wsdl` |
| **Production** | `https://serviciosjava.afip.gob.ar/wslpg/LpgService?wsdl` |

Both endpoints are confirmed in the official AFIP developer manual (v1.24) and in the pyafipws source code.[^4][^2][^1]

### WSAA Service Name

The service name to request a Ticket de Acceso (TA) from the WSAA authentication service is:

```
wslpg
```

This is analogous to `wsfe` for WSFEv1. When calling WSAA's `LoginCms` method, the `<service>` tag in the login ticket request (TRA) must contain `wslpg`.[^5][^1]

### Authentication Structure

Every WSLPG method (except `dummy`) requires an `auth` element with WSAA credentials:[^6][^4]

```xml
<auth>
    <token>string</token>     <!-- Token from WSAA -->
    <sign>string</sign>       <!-- Sign from WSAA -->
    uit>LpgCuitType</cuit>  <!-- 11-digit CUIT of the emisor/representado -->
</auth>
```

The SOAP XML namespace is `http://serviciosjava.afip.gob.ar/wslpg/`.[^6]

## 2. Complete SOAP Methods Catalog

The WSLPG v1.24 exposes **47+ methods** organized into functional groups.[^2][^3][^4]

|---|---|

|---|---|

### Header Fields (Liquidación)

| Field | Type | Required | Validation Notes |
|---|---|---|---|
| `ptoEmision` | `LpgPtoEmision` (1–9999) | Yes | Point of emission, managed by client |
| `nroOrden` | `long` | Yes | Sequential per CUIT+ptoEmision; must be consecutive (error 1508 if not) |
| `cuitComprador` | `LpgCuitType` (11 digits) | Yes | Must be registered in RUOCA |
| `nroActComprador` | `LpgActividadType` | Yes | Buyer's activity code from RUOCA |
| `nroIngBrutoComprador` | `long` | Yes | Buyer's Ingresos Brutos number |
| `codTipoOperacion` | `LpgCodTipoOperacionType` | Yes | `1`=Compra/Venta, `2`=Consignación |
| `esLiquidacionPropia` | `LpgSiNoType` (S/N) | Yes | If own production, buyer/seller data must match |
| `esCanje` | `LpgSiNoType` or `LpgCanjeType` | Yes | `N`=No, `S`=Sí, `P`=Parcial, `T`=Total |
| `codPuerto` | `LpgCodigoPuertoType` | Yes | Port code from `puertoConsultar` |
| `desPuertoLocalidad` | `string` (max 240) | Conditional | Required only when `codPuerto=14` ("Otro") |
| `codGrano` | `LpgCodigoGranoType` (3 digits) | Yes | Grain code from `tipoGranoConsultar` |
| `cuitVendedor` | `LpgCuitType` | Yes | Seller CUIT |
| `nroIngBrutoVendedor` | `long` | Yes | Seller's Ingresos Brutos number |
| `actuaCorredor` | `LpgSiNoType` | Yes | Whether a broker is involved |
| `liquidaCorredor` | `LpgSiNoType` | Conditional | Only when `actuaCorredor=S` |
| `cuitCorredor` | `LpgCuitType` | Conditional | Only when `actuaCorredor=S` |
| `comisionCorredor` | `decimal(3,2)` | Conditional | Broker commission percentage |
| `nroIngBrutoCorredor` | `long` | Conditional | Broker IIBB; only when `liquidaCorredor=S` |
| `fechaPrecioOperacion` | `date` (YYYY-MM-DD) | Yes | Price date |
| `precioRefTn` | `decimal` | Yes | Reference price per ton |
| `codGradoRef` | `string(2)` | Optional | Reference grade code (e.g., `G1`, `G2`, `G3`) |
| `codGradoEnt` | `string(2)` | Optional | Delivered grade code |
| `valGradoEnt` | `decimal(1,3)` | Optional | Delivered grade value (0 → not sent) |
| `factorEnt` | `decimal(3,3)` | Optional | Delivery factor |
| `precioFleteTn` | `decimal(5,2)` | Optional | Freight price per ton |
| `contProteico` | `decimal(3,3)` | Optional | Protein content |
| `alicIvaOperacion` | `decimal(3,2)` | Conditional | IVA rate (10.5 or 21); do not send for Monotributo sellers |
| `campaniaPPal` | `int(4)` | Yes | Main campaign code (e.g., `2324`) |
| `codLocalidadProcedencia` | `int(6)` | Yes | Origin locality code |
| `codProvProcedencia` | `int(2)` | Yes | Origin province code |
| `datosAdicionales` | `string` (max 400) | Optional | Free-text additional data |
| `pesoNetoSinCertificado` | `LpgPesoNetoType` | Conditional | Required if no `ertificados>` are sent |
| `numeroContrato` | `long(15)` | Optional | Contract number (for contract-linked liquidations) |

Fields are validated according to the official manual section 2.4.2.3.[^2][^4]

### Certificados (Certificates) Structure

```xml
ertificados>
  ertificado>
    <tipoCertificadoDeposito>5</tipoCertificadoDeposito>   <!-- 1:F1116/RT, 5:F1116/A, 332:Electronic -->
    <nroCertificadoDeposito>101200604</nroCertificadoDeposito>
    <pesoNeto>1000</pesoNeto>                               <!-- in kg -->
    dLocalidadProcedencia>3</codLocalidadProcedencia>
    dProvProcedencia>1</codProvProcedencia>
    ampania>1213</campania>
    <fechaCierre>2013-01-13</fechaCierre>
  </certificado>
</certificados>
```

Either `certificados` or `pesoNetoSinCertificado` must be provided. Multiple certificates are allowed since v1.5.[^3]

### Retenciones (Withholding Taxes) Structure

```xml
<retenciones>
  <retencion>
    digoConcepto>RI</codigoConcepto>                 <!-- RI=IVA, RG=Ganancias -->
    <detalleAclaratorio>DETALLE</detalleAclaratorio>    <!-- max 30 chars -->
    <baseCalculo>1970</baseCalculo>                     <!-- decimal(8,2) -->
    <alicuota>8</alicuota>                              <!-- decimal(3,2) - rate % -->
    <!-- Optional fields below: -->
    <nroCertificadoRetencion>0</nroCertificadoRetencion>
    <fechaCertificadoRetencion>2023-01-01</fechaCertificadoRetencion>
    <importeCertificadoRetencion>0</importeCertificadoRetencion>
  </retencion>
</retenciones>
```

When `nroCertificadoRetencion`, `fechaCertificadoRetencion`, and `importeCertificadoRetencion` are provided, `alicuota` must be `0` (validation rule 1856). Common codes: `RI` (IVA retention), `RG` (Ganancias retention).[^3][^4]

### Deducciones (Deductions) Structure

```xml
<deducciones>
  <deduccion>
    digoConcepto>AL</codigoConcepto>            <!-- AL=Almacenaje, CO=Comisión, OD=Otras -->
    <detalleAclaratorio>ALMACENAJE</detalleAclaratorio>  <!-- max 50 chars -->
    <diasAlmacenaje>30</diasAlmacenaje>            <!-- Only for AL -->
    <precioPKGdiario>0.01</precioPKGdiario>        <!-- Only for AL -->
    misionGastosAdm>2.5</comisionGastosAdm>     <!-- Only for CO, decimal(3,2) -->
    <baseCalculo>1000</baseCalculo>                 <!-- Not sent for AL -->
    <alicuotaIva>10.5</alicuotaIva>                <!-- IVA rate on deduction -->
  </deduccion>
</deducciones>
```

Validation rules: for `AL` (almacenaje), do not send `baseCalculo`; for `CO` (comisión), `comisionGastosAdm` is required; `diasAlmacenaje` and `precioPKGdiario` only apply to `AL`.[^3]

### Price and Currency

Prices are always expressed in **Argentine Pesos (ARS)** per metric ton. There is no explicit currency field — the service assumes ARS. Key price fields:

- `precioRefTn`: Reference market price per ton
- `precioFleteTn`: Freight cost per ton
- `precioOperacion`: Calculated operation price (returned in response, not sent in request)

The WSLPG calculates `precioOperacion`, `subtotal`, `importeIva`, and all totals server-side and returns them in the response.[^8][^4]

## 4. Error Handling

### Three-Tier Error Model

The WSLPG uses three distinct error mechanisms:[^2][^4]

**Tier 1 — SOAP Faults (exceptional errors):**
Structural errors (malformed XML, invalid tags) and authentication failures are returned as standard SOAP faults:

```xml
<ns2:Fault xmlns:ns2="http://schemas.xmlsoap.org/soap/envelope/">
    <faultcode>ns3:Receiver</faultcode>
    <faultstring>[wscommon_007] La firma no corresponde al token enviado.</faultstring>
</ns2:Fault>
```

**Tier 2 — Format Validation Errors (`erroresFormato`):**
XSD schema validation errors are returned in `<erroresFormato>`. If any format error exists, business validation does NOT execute:

```xml
<erroresFormato>
    <error>
        digo>cvc-complex-type.2.4.a</codigo>
        <descripcion>Invalid content was found starting with element 'x'.
                     One of '{ptoEmision}' is expected.</descripcion>
    </error>
</erroresFormato>
```

**Tier 3 — Business Validation Errors (`errores`):**
Business rule violations are returned as an array of `LpgCodigoDescripcionType`:

```xml
<errores>
    <error>
        digo>1508</codigo>
        <descripcion>El nro de orden no es correlativo...</descripcion>
    </error>
</errores>
```

### Infrastructure Error Codes

| Code | Cause |
|---|---|
| `500` | General application error |
| `501` | General application error |
| `600` | No data found matching the search parameters |
| `700` | Synchronization error |
| `800` | Service not available |

### Common Business Validation Error Ranges

The manual documents hundreds of business validation codes across sections 2.4.2.3, 2.4.3.3, etc.. Key ranges:[^2][^4]

| Code Range | Area |
|---|---|
| `1000–1099` | Operation type / activity mismatches |
| `1100–1199` | Buyer (comprador) validation |
| `1200–1299` | Seller (vendedor) validation |
| `1300–1399` | Broker (corredor) validation |
| `1400–1499` | Certificate validation |
| `1500–1599` | Order number / point of emission / COE |
| `1600–1699` | General field validations (ports, dates, etc.) |
| `1700–1799` | Deduction (deducción) validation |
| `1800–1899` | Retention (retención) validation |
| `1900–1999` | Adjustment-specific validations |
| `2100+` | Contract validation |

### Common Error Scenarios and Solutions

- **Error 1508** — Non-consecutive order number. Solution: call `liquidacionUltimoNroOrdenConsultar` to get the last accepted order number and use the next integer.[^4]
- **Error 1645** — Was "maximum one certificate per liquidation" (removed since v1.5; multiple certificates are now allowed).[^3]
- **Error 1856** — When providing a retention certificate number, `alicuota` must be `0`.[^3]
- **Error 600** — No data found; typically when querying a non-existent COE or order number.[^4]
- **Error 800** — Service temporarily unavailable; implement retry logic.[^4]

## 5. Open-Source Implementations

### pyafipws by Mariano Reingart

The **pyafipws** library is the primary open-source Python implementation and **fully supports WSLPG**.[^9][^10][^3]

- **Repository**: [github.com/reingart/pyafipws](https://github.com/reingart/pyafipws)
- **WSLPG module**: `wslpg.py` — contains the `WSLPG` class with 50+ methods[^9]
- **Version**: 3.35e (latest as of the source code)
- **License**: LGPL-3.0-or-later
- **Author**: Mariano Reingart
- **Install**: `pip install pyafipws` (or `pip install py3afipws` for a Python 3-specific fork)[^11][^12]

#### pyafipws Python Usage Example

```python
from pyafipws.wsaa import WSAA
from pyafipws.wslpg import WSLPG

# 1. Authenticate via WSAA
wsaa = WSAA()
tra = wsaa.CreateTRA(service="wslpg")
cms = wsaa.SignTRA(tra, "certificado.crt", "clave_privada.key")
wsaa.Conectar()
wsaa.LoginCMS(cms)

# 2. Connect to WSLPG
wslpg = WSLPG()
wslpg.Conectar(url="https://fwshomo.afip.gov.ar/wslpg/LpgService?wsdl")
wslpg.Token = wsaa.Token
wslpg.Sign = wsaa.Sign
wslpg.Cuit = "20267565393"

# 3. Health check
wslpg.Dummy()
print(f"App: {wslpg.AppServerStatus}, DB: {wslpg.DbServerStatus}")

# 4. Create and authorize a liquidation
wslpg.CrearLiquidacion(
    pto_emision=1,
    nro_orden=1,
    cuit_comprador="20400000000",
    nro_act_comprador=40,
    nro_ing_bruto_comprador="20400000000",
    cod_tipo_operacion=1,
    es_liquidacion_propia="N",
    es_canje="N",
    cod_puerto=14,
    des_puerto_localidad="DETALLE PUERTO",
    cod_grano=31,
    cuit_vendedor="23000000000",
    nro_ing_bruto_vendedor="23000000000",
    actua_corredor="S",
    liquida_corredor="S",
    cuit_corredor="20200000006",
    comision_corredor=1,
    nro_ing_bruto_corredor="20200000006",
    fecha_precio_operacion="2024-01-15",
    precio_ref_tn=2000,
    cod_grado_ref="G1",
    cod_grado_ent="G1",
    factor_ent=98,
    precio_flete_tn=10,
    cont_proteico=20,
    alic_iva_operacion=10.5,
    campania_ppal=2324,
    cod_localidad_procedencia=3,
    cod_prov_procedencia=1,
    datos_adicionales="TEST LIQUIDATION",
)

wslpg.AgregarCertificado(
    tipo_certificado_deposito=5,
    nro_certificado_deposito=101200604,
    peso_neto=1000,
    cod_localidad_procedencia=3,
    cod_prov_procedencia=1,
    campania=2324,
    fecha_cierre="2024-01-01",
)

wslpg.AgregarRetencion(
    codigo_concepto="RI",
    detalle_aclaratorio="Retencion IVA",
    base_calculo=1970,
    alicuota=8,
)

wslpg.AutorizarLiquidacion()

if wslpg.COE:
    print(f"COE: {wslpg.COE}")
    print(f"Total Neto: {wslpg.TotalNetoAPagar}")
else:
    print(f"Errors: {wslpg.Errores}")
```

The `WSLPG` class exposes all return values as attributes (`COE`, `Estado`, `Subtotal`, `TotalRetencion`, `TotalDeduccion`, `TotalNetoAPagar`, etc.).[^3]

### Afip SDK (afip.py)

A commercial alternative SDK that wraps WSLPG with a simpler API:[^13][^14]

```python

```
```python
from afip import Afip
afip = Afip({"access_token": "YOUR_TOKEN"})
```

### Django Packages

**`django-afip`** (by WhyNotHugo) supports only WSFE (electronic invoicing) and WSAA — it does **not** support WSLPG. There is no known Django package specifically wrapping WSLPG as of March 2026.[^16][^17][^18]

For Django integration, the recommended approach is to use **pyafipws** directly as a library within your Django application, wrapping the `WSLPG` class in your own Django service layer.

## 7. Key Implementation Notes for Django

### Recommended Architecture

```
Django App
├── services/
│   ├── wsaa_service.py       # WSAA token management (cache tokens for 12hrs)
│   ├── wslpg_service.py      # WSLPG business logic wrapper
│   └── afip_config.py        # Endpoints, certs, CUIT config
├── models/
│   ├── liquidacion.py        # Store liquidations + COE
│   └── afip_credential.py    # Store certificates + tokens
└── tasks/
    └── afip_tasks.py         # Celery tasks for async operations
```

### Critical Implementation Considerations

- **Order Number Management**: The `nroOrden` must be strictly sequential per `ptoEmision`. If a request is rejected, reuse the same order number. If you lose connectivity mid-request, use `liquidacionXNroOrdenConsultar` to check if it was authorized.[^4]
- **Token Caching**: WSAA tokens are valid for 12 hours. Cache them rather than re-authenticating per request.
- **Transactional Safety**: AFIP recommends storing `ptoEmision` + `nroOrden` before sending, then reconciling via `liquidacionUltimoNroOrdenConsultar` if the response is lost.[^4]
- **Date Format**: All dates in the WSLPG use `YYYY-MM-DD` format (ISO 8601).[^19]
- **SOAP Library**: pyafipws uses `pysimplesoap` internally. For direct implementation, consider `zeep` (Python SOAP client) which handles the WSDL automatically.

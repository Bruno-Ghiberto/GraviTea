# Implementation Plan: Rust Data Export Pipeline

**Branch**: `020-rust-data-export` | **Date**: 2026-02-26 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/020-rust-data-export/spec.md`

## Summary

Add two Rust/PyO3 functions (`generate_csv`, `generate_xlsx`) to the `gravitea-core` crate for high-performance data export generation. The functions accept rows as `Vec<HashMap<String, String>>` with ordered headers, return `Vec<u8>` byte arrays, and release the GIL during generation. A Python wrapper in the `reportes` app provides a fallback to `csv` stdlib + `openpyxl` when the Rust extension is unavailable.

## Technical Context

**Language/Version**: Rust 1.93.1 (PyO3 0.28) + Python 3.14.3
**Primary Dependencies**: `csv 1` (Rust), `rust_xlsxwriter 0.92` (Rust), `openpyxl` (Python fallback)
**Storage**: N/A — functions return in-memory byte arrays
**Testing**: `cargo test` (Rust-native) + `pytest` (Python integration)
**Target Platform**: Linux (WSL2 dev, Docker prod)
**Project Type**: Library (PyO3 extension module)
**Performance Goals**: 10K rows x 10 cols < 2 seconds (both formats)
**Constraints**: GIL released during generation; ~50-100ms FFI overhead accepted
**Scale/Scope**: Per-request export (1-100K rows typical)

| T-007 | Write Rust-native tests (>=8): CSV roundtrip, BOM, empty, escaping, XLSX roundtrip, numeric detection, column widths, empty XLSX | T-003, T-004 |

**Key design decisions** (from research.md):
- CSV: `csv::WriterBuilder::new().from_writer(Vec::new())` with BOM prepended
- XLSX: `autofit()` first, then `set_column_width()` overrides for explicit widths
- Numeric detection: `value.parse::<f64>()` — success writes number, failure writes text
- GIL: Released after `Vec<HashMap>` extraction via `py.allow_threads()`

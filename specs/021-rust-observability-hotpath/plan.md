# Implementation Plan: Rust Observability Hot Path Acceleration

**Branch**: `021-rust-observability-hotpath` | **Date**: 2026-02-27 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/021-rust-observability-hotpath/spec.md`

## Summary

Replace 24 sequential Python regex operations (`re.sub`) in `normalize_path()` and `sanitize_endpoint_label()` with compiled Rust `Regex` objects using `std::sync::LazyLock<Regex>`. These functions run on every HTTP request via `TraceMiddleware` → `record_request()`. A Python dispatcher (`observability_engine.py`) provides automatic fallback to the existing Python implementation when the Rust extension is unavailable.

**Key design decisions** (from research.md):
- `std::sync::LazyLock<Regex>` for all 24 statics — stable since Rust 1.80, no external crate needed
- Case insensitivity: `(?i)` prefix in pattern strings — identical to `re.IGNORECASE` for ASCII
- Word boundaries: `\b` in Rust regex — identical to Python's `\b` for ASCII keywords
- No empty-match divergence risk — none of our 24 patterns can produce zero-length matches
- Pattern ordering: iterate arrays in declaration order — identical to Python loop

**Pattern implementation detail**:

```rust
use std::sync::LazyLock;
use regex::Regex;

// Path normalizers (2)
static RE_UUID: LazyLock<Regex> = LazyLock::new(|| {
    Regex::new(r"(?i)/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}(?=/|$)").unwrap()
});
static RE_INT_ID: LazyLock<Regex> = LazyLock::new(|| {
    Regex::new(r"/\d+(?=/|$)").unwrap()
});

// Sensitive patterns (16) — all with (?i)
static RE_PASSWORD_RESET: LazyLock<Regex> = LazyLock::new(|| {
    Regex::new(r"(?i)/password[-_]?reset/?").unwrap()
});
// ... (14 more)

// Fallback patterns (6) — all with (?i) and \b
static RE_FALLBACK_PASSWORD: LazyLock<Regex> = LazyLock::new(|| {
    Regex::new(r"(?i)\bpassword\b").unwrap()
});
// ... (5 more)
```

**Python dispatcher pattern** (matches `encryption/utils.py` and `export_engine.py`):
```python
"""
Observability engine — path normalization and endpoint sanitization
with Rust acceleration.

Dispatches to gravitea_rust for performance, falls back to
Python regex when the Rust extension is unavailable.
"""
import logging

logger = logging.getLogger(__name__)

try:
    from gravitea_rust import (
        normalize_path as _rust_normalize_path,
        sanitize_endpoint_label as _rust_sanitize_endpoint_label,
    )
    _USE_RUST = True
except (ImportError, OSError):
    _USE_RUST = False
    logger.warning(
        "gravitea_rust observability not available — using Python fallback"
    )

if _USE_RUST:
    normalize_path = _rust_normalize_path
    sanitize_endpoint_label = _rust_sanitize_endpoint_label
else:
    from apps.core.observability.metrics import (
        normalize_path,
        sanitize_endpoint_label,
    )
```

**Integration change in `metrics.py`** — `record_request()` (line 220-222):
```python
# Before:
normalized_endpoint = normalize_path(endpoint)
sanitized_endpoint = sanitize_endpoint_label(normalized_endpoint)

# After:
from apps.core.observability.observability_engine import (
    normalize_path as _normalize,
    sanitize_endpoint_label as _sanitize,
)
normalized_endpoint = _normalize(endpoint)
sanitized_endpoint = _sanitize(normalized_endpoint)
```

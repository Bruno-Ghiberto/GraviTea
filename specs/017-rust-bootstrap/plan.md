## Summary

Bootstrap the Rust/PyO3/Maturin build toolchain into the GRAVITEA-ERP repository as a foundation layer for 8 subsequent Rust acceleration specs (SPEC-018 through SPEC-025). This spec delivers zero business logic — only infrastructure: Cargo project structure, PyO3 module entry point with a hello-world function, shared error mapping (`GraviteaError` → Python exceptions), Python type stub, fallback import pattern, Docker multi-stage build integration with dependency caching, and developer documentation.

The implementation follows a strict 7-phase sequential plan with 3 agents: ORCHESTRATOR (coordination), RUST-EXPERT (Rust code + RAG queries), and DEVOPS (Docker integration).

**Constraints**: Runtime image size increase ≤15 MB; zero regressions on 2,200+ existing Python tests; fallback pattern mandatory
**Scale/Scope**: Single crate (`gravitea-core`), 2 Rust source files (lib.rs + errors.rs), ~100 lines Rust code

**Structure Decision**: Rust code lives at `rust/gravitea-core/` (repo root), separate from `backend/`. This keeps Python and Rust toolchains independent. The compiled wheel installs into the Python venv via `maturin develop` (local) or Docker multi-stage build (production). The `backend/Dockerfile` gains a `rust-builder` stage prepended before the existing Python builder stage.

## Key Patterns to Follow

### 1. Python Fallback Convention
```python
try:
    from gravitea_rust import hello as _rust_hello
    _USE_RUST = True
except ImportError:
    _USE_RUST = False

def hello() -> str:
    if _USE_RUST:
        return _rust_hello()
    return "Hello from Python (fallback)"
```

### 2. Error Mapping Convention
```rust
#[derive(Error, Debug)]
pub enum GraviteaError {
    #[error("Invalid input: {0}")]
    InvalidInput(String),          // → Python ValueError
    #[error("Crypto error: {0}")]
    CryptoError(String),           // → Python RuntimeError
    #[error("IO error: {0}")]
    IoError(#[from] std::io::Error), // → Python IOError
}
```

### 3. Docker Dependency Caching (Dummy lib.rs + BuildKit Cache Mounts)
```dockerfile
# Step 1: Copy manifests + build deps with dummy source
COPY Cargo.toml Cargo.lock ./
RUN mkdir src && echo "use pyo3::prelude::*; #[pymodule] fn gravitea_rust(_m: &Bound<'_, PyModule>) -> PyResult<()> { Ok(()) }" > src/lib.rs
RUN --mount=type=cache,target=/usr/local/cargo/registry,sharing=locked \
    --mount=type=cache,target=/build/target,sharing=locked \
    cargo build --release --lib

# Step 2: Copy real source + rebuild (only project code recompiles)
RUN rm -rf src
COPY src ./src
RUN --mount=type=cache,target=/usr/local/cargo/registry,sharing=locked \
    --mount=type=cache,target=/build/target,sharing=locked \
    maturin build --release --out /wheels
```
